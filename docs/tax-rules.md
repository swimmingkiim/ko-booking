# 2025년 귀속 계산요소 검증

지원 규칙 버전: `kr-income-2025.1`. 2025년 귀속에 한해 검토한 산식을 실행한다. 2026년 등 다른 연도에 이전 규칙을 자동 적용하지 않는다.

## 지원 범위

| 계산 | 입력 전제 | 반환 결과 |
| --- | --- | --- |
| 종합소득세 기본세율 | 과세표준이 이미 별도로 확정됨 | 과세표준 × 해당 세율 − 누진공제 |
| 단순경비율 사업소득 | 단일 사업장·단일 업종·비공동사업, 해당 방법의 적용 자격과 일반율 적용 가능성을 외부에서 확인 | 수입금액 × (1 − 단순경비율) |
| 인적용역 단순경비율 | 위 전제 및 업종코드 `94****` | 4천만원까지 기본율, 초과분에 초과율 적용 |
| 기준경비율 사업소득 | 위 전제 및 기장 의무 구분과 주요경비의 적격성 확인 | 직접 계산값과 배율 비교값 중 작은 값 |

기준경비율 직접 계산값은 `수입 − 주요경비 − 수입 × 조정 기준경비율`이다. 주요경비는 확인된 매입비용·임차료·인건비의 합계다. 복식부기의무자는 기준경비율의 1/2을 사용한다. 비교값은 단순경비율로 계산한 소득에 간편장부대상자 2.8, 복식부기의무자 3.4를 곱한다. 비교 계산에는 해당 업종의 인적용역 구간도 반영한다.

계산 출력은 `scope=component_only`이고 `final_tax_payable_krw=null`이다. 사업소득금액을 곧바로 과세표준으로 사용하지 않으며, 인적공제 등을 자동 차감하지 않는다. 기본세율 계산에 넣는 값은 매출이나 사업소득이 아니라 별도로 확정한 **과세표준**이다.

## 근거와 버전

규칙은 패키지에 포함되는 [규칙 파일](../ko_booking/rules/2025.json)로 관리한다. 출처 URL, PDF 쪽수, 귀속연도, 검토일, 원문 해시를 함께 기록한다. 각 결과에도 규칙 버전·규칙 SHA-256·근거·계산 단계를 포함한다.

- [국세청 세율 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7667&mi=2227): 2023~2025년 귀속 세율표와 2025년 귀속 예시.
- [2025년 귀속 경비율 자료](https://www.nts.go.kr/nts/na/ntt/selectNttInfo.do?bbsId=1143&mi=2207&nttSn=1350751): PDF 9쪽 산식·배율, 11쪽 인적용역 구간·계산례, 12~13쪽 적용 특례.
- [2025년 귀속 경비율 고시](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000276582): 제2조 적용연도와 제4조 구간. 고시 시행일은 2026-03-30이지만 적용 귀속연도는 2025년이다.

경비율은 2단계 수집기의 특정 버전을 명시해서 읽는다. 검토한 원문·정형 자료 해시와 DB에 저장된 해시 및 실제 내용의 해시를 대조한다. 자료가 갱신되면 새 자료 검토와 규칙 버전 갱신 전까지 계산을 거부한다. 버전 ID는 DB마다 다를 수 있고, 같은 내용의 자료이면 다른 ID도 해시 검증을 거쳐 사용할 수 있다.

## 실행

설치는 [수집기 안내](collectors.md)를 따른다. 기본세율 계산은 DB나 네트워크가 필요 없다.

```sh
python -m ko_booking tax-base --year 2025 --taxable-income 30000000
```

출력의 `calculated_tax_krw_exact`는 `"3240000"`이다.

경비율 자료를 수집하고 `history`에서 `source_key=nts:expense-rates:2025`의 `version_id`를 찾는다. `notice`가 붙은 공지 원문 버전과 구분한다.

```sh
python -m ko_booking --transport curl rates --year 2025
python -m ko_booking history
python -m ko_booking business-income --input examples/business-income-2025.json --rate-version VERSION_ID
```

[예시 입력](../examples/business-income-2025.json)은 공식 계산례의 수입·업종을 사용하고, 적용 조건이 확인되었다고 가정한다. 실제 사용자의 자격을 확인한 파일이 아니다. 결과의 `business_income_krw_exact`는 `"11750000"`이다.

기준경비율 방식은 `method`를 `standard`로 바꾸고 다음 필드를 추가한다.

```json
{
  "bookkeeping": "simple",
  "major_expenses_confirmed": true,
  "major_expenses": {
    "purchases_krw": "20000000",
    "rent_krw": "0",
    "payroll_krw": "0"
  }
}
```

`bookkeeping=simple`은 간편장부대상자, `double`은 복식부기의무자를 의미한다. 기준경비율 산식의 기장 의무 구분이며 실제 장부를 작성했다는 뜻이 아니다. `eligibility_confirmed`는 선택한 추계 방법의 적용 자격을 뜻한다.

## 적용 조건과 정밀도

입력의 `conditions`는 생략하거나 기본값으로 채우지 않는다.

- `single_business=true`, `single_industry=true`, `joint_business=false`: 단일 사업장·업종·비공동사업 확인.
- `eligibility_confirmed=true`: 업종·직전연도와 해당연도 수입·전문직 여부 등의 적용 자격을 외부에서 확인.
- `general_rate_applicable=true`: 자가율·장애인 특례 등 별도 조정 없이 일반율을 적용할 수 있는지 확인.
- `special_adjustments=[]`, `job_stabilization_funds_krw="0"`: 미구현 조정 사항과 일자리안정자금이 없음.

자격 확인 플래그는 증명서류를 검증하는 기능이 아니다. 복수 사업장·복수 업종·공동사업·자가율 조정·장애인 특례·연말정산 사업소득·기타소득 등은 자동 계산 대상으로 확대하지 않는다. 주요경비의 증빙 적격성·재고 조정 등도 외부 확인 사항이다. 이를 확인할 수 없으면 확인 플래그를 켜지 않는다.

금액 입력은 원 단위 비음수 정수 또는 숫자 문자열이며 구현상 최대 18자리다. 이진 부동소수점·빈 값·음수·지수 표기·쉼표를 허용하지 않는다. 내부 `Decimal` 계산 문맥을 고정해 앱의 전역 정밀도 설정으로 결과가 달라지지 않는다. 출력은 십진 문자열이며 신고 단수 처리를 하지 않는다. 예를 들어 과세표준 14,000,001원의 계산요소는 `"840000.15"`로 반환한다.

경비율 누락이나 0 값을 적용 가능한 세율로 추정하지 않고 재검토를 요구한다. 기준경비율 직접 계산값이 음수인 경우도 임의로 0으로 바꾸지 않고 미지원으로 처리한다. 소득공제·세액공제·감면·기납부세액·지방소득세·최저한세·신고 단수 처리·최종 납부 또는 환급액은 포함하지 않는다.

## 검증 재실행

```sh
python -m unittest discover -s tests -v
```

[테스트 사례](../tests/fixtures/tax_cases_2025.json)는 공식 예제와 공식 산식으로 만든 합성 예제를 구분한다. 모든 세율 경계의 직전·경계·직후 값과 결정적 난수 100개를 별도의 구간별 누적 계산으로 대조한다. 실제 납세자 신고 결과 또는 세무전문가의 검토를 대체하는 검증은 아니다.
